# 中文短评情感分析器

用纯 Python 标准库实现的中文短评正负面判断工具：字符 n-gram + 多项式朴素贝叶斯，支持 5 折交叉验证、单条预测和模型保存。

## 项目背景与要解决的问题

- 电商、外卖、影评、酒店等场景里，用户短评数量大、更新快，人工逐条看正负面成本高，需要一个能快速给出「正面/负面 + 置信度」的基线工具。
- 中文没有天然空格，分词器又依赖第三方词典，所以这个项目刻意**不引入分词**，直接用字符 1-gram / 2-gram 作为特征，把「不、没、太」这类字也变成可见信号。
- 真实短评里大量出现否定（"不是不好用"）、反讽（"真是谢谢你"）、混合情感（"东西不错但物流太慢"）和极短句（"就这？"），这些难例才是小样本情感分类的真实难点，也是本项目数据构造时刻意覆盖的部分。

## 技术方法

1. **特征**：把一条短评拆成字符序列，统计字符 1-gram 与相邻字符 2-gram 的出现次数；中文的"不错""太慢""失望"等评价线索会被 2-gram 直接捕获，不需要分词。全量 240 条共得到 3500 维特征。
2. **模型**：多项式朴素贝叶斯（Multinomial NB）。对每个类别统计特征出现次数，用拉普拉斯平滑估计条件概率 `P(f|c) = (count(f,c) + α) / (总词数(c) + α·V)`，预测时比较 `log P(c) + Σ count(f)·log P(f|c)`，全程 log 空间计算避免下溢。
3. **调参**：平滑系数 α 从 {0.1, 0.3, 1.0} 中选。5 折的每一折在训练集内部再分层划出 20% dev，用 dev 准确率选 α，再在完整训练集上训练、预测测试折；α 的选择不接触测试折。
4. **评估**：自己实现分层 5 折切分（类内打乱后轮转分配，固定 `random.seed(42)`），把 240 条样本的 out-of-fold 预测拼起来统一算 accuracy、每类 precision/recall/F1 和混淆矩阵。
5. **置信度**：NB 的原始概率通常接近 0/1。额外用 dev 集做单参数温度缩放 `p = sigmoid((logit₁ - logit₀) / T)`，网格搜索最小化 log loss，让置信度更可读（本模型 T=4.0）。

## 快速开始

```bash
python main.py --eval                          # 分层 5 折交叉验证，打印全部指标
python main.py --predict "东西不错但物流太慢"    # 预测单条短评（未训练时自动用全量数据训练）
python main.py --train                         # 全量训练并保存 model.json
```

要求：Python 3（只依赖标准库，无第三方包）。数据文件为 UTF-8 编码；脚本入口已对 stdout 做 UTF-8 重配置，避免 Windows 控制台 GBK 报错。

## 局限与改进

1. **反讽和强弱程度词仍会错**：模型能识别语料里出现过的反讽句式（如"真是谢谢你，让我多等了两小时"判为负面），但换成没见过的说法就不稳定；"还行""一般"这类弱评价也会判错（实测"还行"被判负面、"味道一般，不算难吃"被判正面），因为字符词袋无法建模否定辖域和语气。
2. **置信度只能参考、不能当概率用**：温度缩放后大部分样本置信度更合理，但 logit 差距很大的样本仍会接近 1.0000；且小样本 dev 只有 48 条，T 本身估得比较粗。
3. **规模与领域覆盖有限**：240 条自建语料无法覆盖真实短评的长尾表达，模型在跨领域、新词和更长的评论上会退化；若要上线，需要扩充到数千条以上并做嵌套交叉验证或按领域分别建模。
